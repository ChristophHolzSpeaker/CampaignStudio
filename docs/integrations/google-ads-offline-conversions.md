The table records the agreed native action IDs, not proof that their automatic triggers are deployed. The native reconciler/default mapping implementation remains on the unfinished `wip/offline-conversions-service-account` branch; it is not part of this visit-outcome change. Automatic native events still require their own deployment and mappings. Manual event defaults are defined in `src/lib/tracking/manual-outcomes.ts`.

Manual outcomes can address either a journey or an exact visit through `POST /api/public/v1/campaign-visits/{id}/outcomes`. The visit endpoint creates no lead journey and uses only explicit visit-to-click provenance. At the owner’s explicit request, `company_identified` and `lead_marked_eligible` both default to action `7755799338` in customer `2354667197`. Campaign configuration can override either mapping. The dashboard must send only one of those event names for a decision; no new company-specific Ads action is created.

The owner-selected manual visit consent policy defaults to GRANTED and reports `owner_default` provenance. Explicit visitor denial blocks delivery. These are server-side conversions, so the Google Ads label is blank and the dashboard must not also fire them through GTM. Read the exact readiness, retry and deployment contract in [the tracking guide](../../src/lib/artifacts/tracking-guide.md).
